# Database setup

Use a newly created, empty MySQL 8.0-compatible database. The schema uses InnoDB, `utf8mb4`, and `utf8mb4_0900_ai_ci`.

From the `backend` directory, configure `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in a private environment file or hosting settings. `DB_SSL=true` enables TLS. Never commit `.env` or put credentials in this document.

Run the explicit setup commands in order:

```text
npm run db:migrate
npm run db:seed:reference
npm start
```

The initial migration is for an empty database only. The migration runner refuses an untracked non-empty database and does not drop tables. MySQL DDL is not transaction-safe as a whole; if the baseline fails partway through, stop and review the disposable database rather than retrying blindly. Do not run the baseline against an existing production database without a separately reviewed migration plan and backup.

The reference seed installs the six item statuses, the existing city/region location options, and five approved item categories: Phone, ID Card, Wallet, Document, and Other. Category IDs are generated by the database; category names are the stable reference values. The seed is idempotent and requires no fixed category IDs. Startup checks refuse to serve while categories are absent.

The original `backup.sql` contains real production data and must never be used to initialize a public/demo database. Synthetic demo data, if needed later, will use a separate optional process and is not part of these commands. No users or administrators are created by migration or reference seeding.
